## Reading rule and scope

An `id` below is a valid SQLite `messages.id`, not an invented ticket number. Owner text in a `role=user` row was checked against injected notices, compaction handoffs, image encodings and same-timestamp cumulative renderings. Short replies such as “Yes,” “A,” and “2” are interpreted only against the immediately preceding assistant proposal. Assistant reports are proposals or completion **claims**; they do not establish current V2 state or V3 acceptance. Historical requests to run, commit, push, deploy or alter the scheduler were instructions in V2 at their time, not commands for this P0.1 task. Injected notices and compaction references carry stale timestamps, so `(timestamp, id)` order is not strict chronology for those rows; owner rows are unaffected (see METHOD.md limits).

Two scopes are kept separate. **Owner authorization** (PLAN.md line 13, 27 Sep 2026: “Read PLAN.md in full and begin following it.”) covers the whole plan's local discovery and implementation gates; new repository bindings, external publication, production scheduling changes and live cutover retain explicit owner-approval boundaries. The **P0.1 packet write limit** (PLAN.md status block: the worker writes only `docs/REQUIREMENTS.md` and `evidence/P0/chronology/`, and reads sources only) is a delegation limit for this child task, not the extent of the owner's authorization.

The sessions end on 26 September 2026. IDEA.md says to fix and refactor V2 into a new project. PLAN.md contains later planning synthesis and the current V3 scope; some PLAN §2 statements have no direct owner wording in these two sessions and are marked as interpretation below. P0.2–P0.8 must validate actual artifacts and remaining decisions.
